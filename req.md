# 7. MOTION DESIGN & INTERACTION SYSTEM

Motion is a major part of this portfolio's identity.

Use GSAP as the primary animation engine.

Recommended tools:
- GSAP.
- ScrollTrigger.
- Three.js for selected 3D experiences.
- CSS transforms and transitions.
- SVG animations where appropriate.

### A. Cursor Interactions

Implement refined interactions:

- Custom cursor treatment on desktop, if it improves usability.
- Subtle cursor-following light or spotlight.
- Magnetic button movement.
- Interactive project previews.
- Smooth hover transitions.
- Contextual cursor labels such as "Explore", "View Project", and "Read".

Never hide or disable the standard cursor when it harms usability.

### B. Hover Effects

All interactive elements should feel responsive.

Examples:
- Buttons transition from black to soft white.
- Text changes smoothly on hover.
- Project thumbnails slightly zoom.
- Cards reveal supplementary information.
- Borders animate subtly.
- Arrows move a few pixels.
- Links receive a soft illuminated treatment.

Keep the hover effect monochromatic.

### C. Scroll Animations

Use GSAP ScrollTrigger for:

- Text reveal animations.
- Section entrance transitions.
- Staggered project reveals.
- Image parallax.
- Pinned storytelling sections where justified.
- Layered depth effects.
- Subtle horizontal movement.

Animations must feel smooth, premium, and intentional.

### D. Continuous Ambient Motion

Use carefully controlled continuous motion:

- Slowly floating abstract objects.
- Subtle background particles.
- Gentle geometric rotations.
- Very slow depth movement.
- Cursor-reactive 3D elements.

Avoid making every element move continuously.

### E. Page Transitions

Create smooth transitions between Home and Work.

Transitions should be quick and elegant. Never force users to wait through lengthy intro animations.

# 8. TECHNICAL REQUIREMENTS

Preferred stack:

- Next.js.
- React.
- TypeScript.
- Tailwind CSS.
- GSAP.
- Three.js / React Three Fiber where justified.
- Lucide icons.

Use Next.js App Router unless the existing repository has a compelling reason to use another architecture.

### Architecture

- Reusable components.
- Centralized design tokens.
- Modular animation utilities.
- Separated project data.
- Reusable case-study components.
- Maintainable content structure.
- Clean routing.
- Semantic HTML.

Project and article content should be stored separately from presentation components so that new work can be added without redesigning the site.

### Responsive Design

Support:
- Desktop.
- Laptop.
- Tablet.
- Mobile.

Mobile must receive its own interaction strategy.

Do not simply shrink desktop animations onto mobile.

Disable expensive 3D effects on devices where they would negatively affect performance.

### Accessibility

- Keyboard-accessible navigation.
- Visible focus indicators.
- Proper contrast.
- Semantic headings.
- Accessible buttons and links.
- Reduced-motion support using prefers-reduced-motion.
- No essential information hidden behind hover.

### Performance

Target excellent Core Web Vitals and Lighthouse results.

Requirements:
- Optimize images.
- Lazy-load below-the-fold media.
- Minimize unnecessary JavaScript.
- Avoid expensive React re-renders.
- Optimize Three.js rendering.
- Avoid scroll-jacking.
- Keep animations GPU-friendly.
- Respect reduced-motion preferences.
- Ensure the first meaningful content appears immediately.

The website should remain fast even with animation enabled.

### SEO

Implement:
- Page-specific metadata.
- Open Graph metadata.
- Structured data where appropriate.
- Sitemap.
- Robots.txt.
- Descriptive URLs.
- Semantic content.
- Social sharing previews.

The site should be discoverable for software engineering, full-stack development, AI engineering, and freelance development services.
